<threat_model>
## Trust boundaries

| Boundary | Description |
| --- | --- |
| Local WebView → Tauri runtime | The renderer can invoke the explicitly authorized status command and manage its event listener. |
| Rust adapter → local WebView and logs | Public status snapshots and sanitized errors cross the boundary. |
| Registry dependencies → build | npm and Cargo fetch the approved identifiers and resolve the lockfiles. |

## STRIDE threat register · ASVS L1

| Threat ID | Category | Component | Severity | Disposition | Mitigation plan |
| --- | --- | --- | --- | --- | --- |
| T-01-01 | Elevation of privilege | Tauri capability and application manifest | high | mitigate | Register the sole command in src-tauri/build.rs, grant it with only event listen and unlisten on the local main window in src-tauri/capabilities/main.json, and check the allowlist and generated context in the desktop tests. |
| T-01-02 | Information disclosure | Status error, event, and diagnostics | high | mitigate | Emit only the typed snapshot from Rust to the caller and serialize fixed safe errors. Assert synthetic private details stay out of the error contract and frontend. |
| T-01-03 | Tampering | Status event and display | medium | mitigate | Withhold WebView event emission in the capability and scope delivery to the calling window. Make the command result authoritative and verify the UI handles event loss. |
| T-01-08 | Tampering | Desktop Cargo dependency resolution | high | mitigate | Use the audited Tauri crate identifiers and verify the updated Cargo lockfile sources. |
</threat_model>
